## Locked decisions (do not relitigate without a reason)

| Area                 | Decision                                                                                                                                                                                                                               |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Web data access      | **RSC + Server Actions only.** No client-side query library. URL search params drive filtered/paginated lists.                                                                                                                         |
| Content contract     | Frozen in `@agency/types`. Only ever **extended**, never reshaped. Envelope is `{ success, data, meta }`.                                                                                                                              |
| The data seam        | `apps/web` never calls `fetch`/a DB directly. Everything goes through `@agency/sdk`. See below.                                                                                                                                        |
| Backend (Stage 3b)   | Node + **Express** + **MongoDB/Mongoose**, custom JWT (argon2), Cloudinary media, deployed to Vercel serverless + MongoDB Atlas.                                                                                                       |

## The data seam (the one thing to understand)

`apps/web/src/lib/content/client.ts` is the **only** place the data origin is
decided:

```ts
export const content = createContentClient({
  transport: fixtureTransport(dataset), // ← now: typed placeholder data
});
// Stage 3b: swap to httpTransport({ baseUrl: process.env.CMS_API_BASE_URL, revalidate: 300 })
```

- **Now**: `fixtureTransport` reads typed modules in `apps/web/src/content/*`
  and does in-memory filter / sort / paginate, returning the same
  `{ success, data, meta }` envelope the future API will.
- **Stage 3b**: change that one file to `httpTransport` + set an env var.
  Pages, components, `@agency/types` and every `src/lib/content/*` accessor stay
  untouched. `apps/web/src/content/*` then becomes the seed source for the DB.

Pages are `async` Server Components that call `src/lib/content/<type>.ts`
accessors (`getServices`, `getBlogPost`, …) and pass the result to presentational
components. The contact form is a Server Action (`src/lib/actions/contact.ts`)
plus a mirror route handler (`src/app/api/contact/route.ts`), both funnelling
through `src/lib/leads/submit.ts`, which sends email via `src/lib/email/*`.

## The colour system

Single source of truth: **`packages/config/colors/palette.mjs`**.

Run `pnpm --filter @agency/config gen` (also runs inside `turbo build`) to
regenerate two files from it — **do not edit these by hand**:

| Generated file                        | Consumed by                                                                                                                                                    |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/config/tailwind/tokens.css` | Tailwind v4 — `@import`ed by each app's `globals.css`; produces the utility classes (`bg-primary`, `text-muted-foreground`, `bg-chart-1`, `bg-primary-100`, …) |
| `packages/config/colors/index.ts`     | Code that needs a colour **value**: `viewport.themeColor`, OG images, transactional email, charts. `import { colors, cssVar } from '@agency/config/colors'`    |

- **Semantic tokens** (`--primary`, `--muted`, `--success-foreground`, …) are
  theme-aware (light on `:root`, dark on `.dark` via next-themes `class`).
- **Numeric scales** (`--color-primary-50..950`, `--color-neutral-50..950`) are
  absolute — they do not switch with the theme; use them for bespoke tints.
- `--chart-1..5` are theme-aware categorical colours for recharts.
- Re-tinting the whole system: change `BRAND_HUE` and the seed values in
  `palette.mjs`, then regenerate.

The only hardcoded hex left in `apps/web` is the WhatsApp/Telegram brand green
and blue in `src/components/shared/floating-contact.tsx` — intentional.
